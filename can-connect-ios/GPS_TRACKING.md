# GPS routes with scanner recordings

Automatic and manually started scanner recordings now start the iPhone's Core Location recorder alongside OBD polling. Both streams belong to the same saved trip. Connect → Devices → This iPhone shows location status during scanner recording as well as phone-only recording. The existing screens, card layout, colours and soot percentage are unchanged.

For an automatic scanner trip that begins while locked or another app is open, Always location authorization is required. In Connect → Devices, tap the existing This iPhone card to request it; Precise Location should be enabled. While Using remains supported for sessions started with DriveLine open, and those sessions can continue into the background. The app does not silently upgrade authorization.

Location permission is required for routes; denied/revoked location access does not end an MX+ recording. That session continues with its measured vehicle readings, and a temporary message explains why GPS is missing. Phone-only GPS retains its existing permission/error behaviour. Finish stops GPS after the recording is durably saved. A temporary scanner loss now retains GPS during the reconnect grace period described below. App switching checkpoints the same draft and leaves location updates running using the existing location background mode. iOS still controls background launch and execution; force-quitting cannot be overridden.

GPS fixes must be fresh, obtained since this recording's location updates began, and have horizontal accuracy within 50 metres. Recorded points reject backwards/duplicate timestamps and implausible jumps. Map lines break across gaps over 30 seconds. Scanner distance remains integrated from measured vehicle speed; GPS points do not add distance again. Phone-only distance is calculated from consecutive valid GPS points. No missing coordinates are inferred from speed or filled from a map.

The local recording/archive retains coordinates, accuracy, timestamps and available GPS speed. Mac uploads include both the raw scanner responses and separate GPS samples. The Mac retains the exact original upload and imports the coordinates and vehicle signals into its trip. GPS speed is not labelled as ECU vehicle speed. Old scanner recordings that contain no coordinates cannot acquire a historical route from this fix.

Validation includes injected scanner/GPS lifecycle tests, permission failure, background checkpoint, save/reload/export, distance isolation, delayed callback timestamps, and route gaps. The UI test drives Core Location with explicitly synthetic coordinates while a TCP scanner fixture supplies OBD data, switches to the Home Screen, then checks the saved route map. Mac tests and an isolated receiver integration test verify mixed GPS/OBD uploads, coordinates, receipts, deduplication and original preservation.

Physical acceptance remains a new drive with the iPhone and MX+: allow location and Precise Location, confirm GPS active before departure, then check the saved route and its Mac copy once parked. Software simulations do not verify GPS reception in the actual car or a full locked-screen drive.

## Scanner trip continuity (build 22)

Automatic connection requires the saved MX+ serial number on the selected real vehicle profile. A decoded engine RPM of at least 400 is required to start an automatic trip; accessory presence, ignition-only responses, GPS movement, walking, CarPlay and rides in other vehicles do not independently create trips. If the profile has a VIN, a missing or mismatched scanner VIN blocks polling. Profiles without a VIN rely on their explicitly bound adapter; moving that adapter to another car requires reviewing the selected vehicle. The user's existing Jetta profile is bound to its MX+ but currently has no saved VIN.

On a temporary scanner disconnect, retain the draft ID, GPS session, route and Live Activity. Retry the same saved accessory with backoff and append new real OBD responses to that same draft after identity validation. Do not fabricate readings or integrate speed across long gaps. The grace period is 120 seconds from the last ECU response, never extended by failed reconnect attempts. If it expires, finish at the last confirmed ECU response and exclude provisional GPS points afterward so a walk or ride after leaving the vehicle is not retained. The deadline is checkpointed; recovery after app termination likewise excludes that unconfirmed tail. Explicit Disconnect ends and saves the trip, while manual Finish suppresses immediate automatic restarting.

Engine-off is inferred only from repeated zero-RPM responses spanning at least three seconds, with a fresh zero vehicle-speed reading. A moving vehicle, isolated zero, missing reply, stale speed or disconnected scanner cannot satisfy this rule. Confirmation ends the trip quietly and stops GPS. Continued ignition-only responses do not start another trip; a subsequent running-engine reading can start a new one. This conservative rule is intended for this Jetta; automatic engine stop/start on other vehicles needs separate validation.

The screens, card layout, soot percentage, app identity and saved recordings remain unchanged. Physical acceptance requires a running-engine start, a short MX+ outage and return with the same trip ID/GPS trace, confirmed engine shutdown, and a subsequent locked-screen engine start. The app cannot force iOS to reconnect an unavailable Bluetooth Classic accessory. A running engine and configured scanner remain required for automatic starts even with Always location access.

Validation for build 22: the full local Xcode suite passed 97 tests with three hardware/opt-in checks skipped. The signed device build passed and installation/launch preserved all 32 saved recordings, vehicle profiles, transfer state, server settings and regeneration baseline. The user is away from the car, so same-trip MX+ reconnection and physical engine-off boundaries remain unverified. Test fixtures exercise GPS retention, unchanged trip identity, recovery, expired gaps, wrong/unknown VIN rejection, no automatic start for ignition-only responses, engine-off confirmation and starting a separate trip afterward. No screen-layout or reading-card changes were made.
